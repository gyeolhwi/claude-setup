# Obsidian 카테고리 설정

이 파일은 Obsidian 커맨드들이 참조하는 카테고리 설정 파일이다.
`/obsidian-init`이 생성하며, 사용자가 자유롭게 수정할 수 있다.

---

## 폴더 구조

```
00_Sandbox/          # 미분류 파일 임시 보관
01_문서템플릿/        # 문서 템플릿
Clippings/           # 웹 클리핑
10_Dev/
  ├── Backend/
  ├── Frontend/
  ├── Server/
  ├── DevOps/
  ├── Architecture/
  ├── Standards/
  ├── Ai/
  └── Design/
20_Work/             # 업무 문서 — 회사 카드 + client 필드가 붙은 문서
30_Tools/
40_Personal/
  └── 감상기록/
99_Archive/          # 분류 불명확, 임시 보관, 삭제 예정
```

## 인덱스 파일 매핑

> ⚠️ 인덱스 파일명은 **`_` 접두사**로 시작한다. 파일 탐색기에서 폴더 맨 위에 고정하기 위함이다.
> 이유: Obsidian(ICU 콜레이션)은 이모지를 숫자보다 **먼저** 정렬한다. 따라서 `00_` 같은 숫자 접두사는
> 이모지로 시작하는 다른 파일들보다 **아래로** 내려간다. `_`만이 이모지 앞에 온다.
> 같은 폴더에 인덱스가 여러 개면 허브 인덱스에 `__`를 써서 한 단계 더 위로 올린다.
>
> **wikilink는 `_`를 포함한 실제 파일명 그대로 쓴다** (`[[_💼 Work 인덱스]]`).

| 폴더 | 인덱스 파일명 = wikilink 이름 |
|------|------------|
| 10_Dev/ | `_💻 개발 인덱스` |
| 10_Dev/Backend/ | `_⚙️ Backend 인덱스` |
| 10_Dev/Frontend/ | `_⚛️ Frontend 인덱스` |
| 10_Dev/Server/ | `_🖥️ Server 인덱스` |
| 10_Dev/DevOps/ | `_DevOps 인덱스` |
| 10_Dev/Architecture/ | `_Architecture 인덱스` |
| 10_Dev/Design/ | `_🎨 Design 인덱스` |
| 10_Dev/Ai/ | `_🤖 Ai 인덱스` |
| 10_Dev/Standards/ | `_📋 컨벤션 인덱스` |
| 20_Work/ | `_💼 Work 인덱스` |
| 30_Tools/ | `_🛠️ Tools 인덱스` |
| 40_Personal/ | `_👤 프로필 인덱스` |
| 40_Personal/감상기록/ (허브) | `__🎞️ 감상 기록 인덱스` |
| 40_Personal/감상기록/ (책) | `_📖 책 인덱스` |
| 40_Personal/감상기록/ (영화) | `_🎬 영화 인덱스` |
| 40_Personal/감상기록/ (애니) | `_🌸 애니 인덱스` |
| 00_Sandbox/ | `_📥 Sandbox 인덱스` |
| Clippings/ | `_📎 Clippings 인덱스` |
| 01_문서템플릿/ | 없음 — 템플릿 폴더 (`00_템플릿_사용규칙.md`이 허브 역할) |
| 99_Archive/ | 없음 — 삭제 예정 보관함 |

> ⚠️ **인덱스에 `aliases`를 쓰지 말 것.** `aliases`로 `_` 없는 이름을 만들고 본문에서 `[[💼 Work 인덱스]]`로
> 링크하면, Obsidian이 alias 해석에 실패할 때 **미해결 링크가 유령 노드로 떠서 같은 인덱스가 그래프뷰에
> 두 개로 겹쳐 보인다**(`💼 Work 인덱스` + `_💼 Work 인덱스`). 허브 16개가 전부 두 배가 되어 그래프가 꼬인다.
> 링크 대상을 실제 파일명으로 유지하면 alias 해석에 의존하지 않아 유령이 생길 수 없다.

새 인덱스를 만들면 북마크(`.obsidian/bookmarks.json`)에도 등록한다.

### 인덱스 섹션 규약

| 섹션 | 성격 | `/obsidian-index` 자동 갱신 |
|------|------|------------------|
| `## 📑 목록` | 그 폴더의 문서 목록 | ✅ 여기에만 추가됨. **모든 인덱스에 필수** |
| `## 📂 카테고리` | 하위 폴더 인덱스 링크 | ❌ 수동 |
| 그 밖의 섹션 (`## 🏢 회사 카드`, `## 🔗 관련 링크` 등) | 수동 큐레이션 | ❌ 수동 |

예외: `40_Personal/감상기록/`의 허브 `__🎞️ 감상 기록 인덱스`는 `## 📑 목록`이 없다.
그 폴더의 문서는 `tags`(`books`/`movie`/`anime`)에 따라 매체별 인덱스로 등록된다.

## 표준 태그 어휘

아래 태그를 우선 사용한다. 목록에 없는 개념은 소문자 하이픈 형식으로 새로 만든다.

> ⚠️ 소속·회사·기관 고유명사(예: 우리회사, 협력사B, 재단C)는 **태그가 아니라 `client` 필드**에 넣는다. 태그는 주제 전용.

| 카테고리 | 사용할 태그 |
|---------|-----------|
| **언어** | `java` `javascript` `typescript` `python` `html` `css` |
| **프레임워크** | `spring` `spring-boot` `react` `next` `vue` |
| **백엔드** | `backend` `database` `mysql` `jpa` `api` `rest` `oauth` `jwt` `servlet` `jsp` |
| **프론트엔드** | `frontend` `styled-components` `css-in-js` `framer-motion` |
| **서버/인프라** | `server` `aws` `docker` `nginx` `linux` `ssh` `dns` |
| **DevOps** | `devops` `cicd` `github-actions` `deployment` |
| **아키텍처** | `architecture` `design-pattern` `mvvm` |
| **디자인** | `design` `figma` `ui` `ux` `glassmorphism` `theme` |
| **AI** | `ai` `claude-code` `prompt` `agent` |
| **도구** | `tools` `ide` `git` `obsidian` `openclaw` `telegram` |
| **업무** | `work` `client` `payment` |
| **개인** | `personal` `goal` `idea` `portfolio` `sensitive` `recipe` `finance` |
| **컨벤션** | `convention` `standard` |
| **웹 클리핑** | `clippings` |
| **감상 — 매체** | `media` `books` `movie` `anime` |
| **감상 — 장르** ※한글, 예시 | `판타지` `액션` `역사` `미스터리` `공포` `로맨스` |
| **감상 — 제작국** ※한글, 예시 | `한국영화` `일본영화` `외국영화` |

> ※ **감상기록 장르·제작국 태그만 한글을 쓴다** (`40_Personal/감상기록/`). 나머지는 전부 소문자 영문.
> 장르는 검색·필터가 목적이고 한글로 찾는 게 자연스러워서 둔 예외다. `판타지`를 `fantasy`로 바꿔도
> 얻는 게 없다. 다만 **매체 축(`books`/`movie`/`anime`)은 영문 그대로** 두어 인덱스 분류와 맞춘다.
> 장르·제작국 목록은 **예시**이니 본인 취향에 맞게 바꿔 쓴다.
>
> 세 축이 한 `tags` 필드에 섞여 있다 (매체 + 장르 + 제작국). 규모가 작을 땐 문제없지만,
> 늘어나서 헷갈리면 중첩 태그(`장르/판타지`, `국가/한국`)로 분리하는 걸 고려한다.

## status 값

frontmatter의 `status`는 아래 단일값 중 하나로 지정한다.

| 상태 | 기준 |
|------|------|
| `done` | 내용이 완성된 문서 |
| `wip` | 명백히 작성 중인 문서 |
| `seed` | 아이디어 메모, 초안, 내용이 짧거나 미완성 |
| `hold` | 작성 보류 중인 문서 |
| `reference` | 가이드/규칙/기준 문서 |
| `wiki` | 용어/개념 정의 문서 |
| `todo` | 할 일/처리 예정 메모 |
| `rfc` | 논의·검토 중인 제안/초안 |

## client 필드

회사·클라이언트 업무로 작성된 문서는 `client` 필드로 얽힌 회사·기관을 표시하고 **`20_Work`에 둔다.** `client`가 붙으면 주제 폴더가 아니라 `20_Work`로 간다 (우리회사 배포 문서 → `10_Dev/DevOps`가 아니라 `20_Work`). 소속명은 `tags`가 아니라 `client` 필드에만 둔다.

**리스트(multitext)로 쓴다.** 관련 회사를 가까운 순서로 나열: 내 소속 → 고객사 → 벤더/서비스. 값이 하나여도 리스트로 쓴다.

```yaml
client:
  - 우리회사      # 내 소속 (항상 첫 번째)
  - 고객사A      # 고객사
  - 결제벤더      # 벤더/서비스
```

`client: 우리회사 고객사A 결제벤더`처럼 한 줄에 이어 쓰면 값 하나짜리 문자열이 되어 필터가 걸리지 않는다. `.obsidian/types.json`에 `"client": "multitext"` 등록이 전제다.

| 판단 | 처리 |
|------|------|
| 내용/description에 특정 회사·클라이언트 업무임이 분명 (예: "우리회사 고객…") | `client` 리스트 추가 → `20_Work` |
| 본문/태그에 소속·기관 고유명사가 박혀 있음 | 해당 값을 `client`로, 태그에서는 제거 |
| 개인 학습·기록·취미 | `client` 없음 (개인 노트) → 주제 폴더 |

업무와 무관하게 **재사용 가능한 일반 기술 지식**(특정 회사 얘기가 없는 배포 절차·DNS 설정법 등)은 `client` 없이 `10_Dev/` 주제 폴더에 둔다.

## 문서 단일성 원칙

**문서 하나가 필요한 정보를 스스로 담는다.** 다른 문서를 찾아가게 만드는 포인터 규칙을 만들지 않는다.

| 하지 말 것 | 대신 |
|-----------|------|
| "이 값은 X 문서에 모아둔다" 식으로 내용을 딴 데로 빼는 규칙 | 필요한 정보는 그 문서 안에 직접 기입 |
| 여러 문서에 흩어질 정보를 위한 중앙 허브 문서 신설 | 관련 문서끼리 wikilink로 연결만 (백링크 활용) |

### 계정 정보

| 대상 | 위치 |
|------|------|
| **내 계정** (개인·가족, 그리고 회사에서 쓰는 내 계정 — 예: 우리회사 dev Codex) | `40_Personal/🔒 계정 정보` |
| **거래처·클라이언트 계정** (그 회사의 도메인 관리자·호스팅 등) | 해당 회사 카드 안에 직접 기입 |

`🔒 계정 정보`는 **내 계정 전용 개인 문서**다. 거래처 자격증명을 여기로 모으지 않으며, 회사 카드가 이 문서를 자격증명 저장소로 참조하게 만들지 않는다.
