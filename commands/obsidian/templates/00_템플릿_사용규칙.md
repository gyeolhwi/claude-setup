# 📋 템플릿 사용 규칙

> Document 볼트의 모든 문서에 적용되는 공통 규칙을 정의합니다.

---

## 공통 YAML Frontmatter

모든 문서는 아래 frontmatter를 필수로 포함합니다:

```yaml
---
status: done
tags:
  - 태그1
  - 태그2
client:                 # (선택) 업무 노트만 — 리스트로 작성. 없으면 개인 노트
  - 우리회사
  - 고객사A
description: "한 줄 요약 — AI 검색 및 Obsidian 호버 미리보기용"
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

| 필드 | 필수 | 설명 | 값 예시 |
|------|------|------|---------|
| `status` | ✅ | 문서 상태 (단일값) | `done` |
| `tags` | ✅ | 소문자 영문, 2~5개 권장 — 주제만 (소속/기관명 금지). 감상기록 장르·제작국만 한글 예외 | `- backend` |
| `client` | ⬜ | (선택) 업무 노트만 — 얽힌 회사·기관 **리스트**. 없으면 개인 | `- 우리회사` |
| `description` | ✅ | 한 줄 요약 — AI 검색 및 호버 미리보기용 | `"JWT 인증 전체 흐름 가이드"` |
| `created` | ✅ | 최초 작성일 | `2026-02-20` |
| `updated` | ✅ | 최종 수정일 | `2026-02-20` |

### status 값 정의

| 값 | 의미 |
|----|------|
| `done` | 완성된 문서 |
| `wip` | 작성 중 |
| `seed` | 아이디어/초안 — 짧거나 미완성 |
| `hold` | 보류 중 |
| `reference` | 가이드/규칙/기준 (인덱스 파일에 사용) |
| `wiki` | 용어 정의, 개념 설명 |
| `todo` | 할 일/처리 예정 메모 |
| `rfc` | 논의·검토 중인 제안/초안 |

### client 필드 (업무 노트 구분)

회사·클라이언트 업무로 작성한 노트는 `client` 필드로 얽힌 회사·기관을 표시합니다.

- **선택 필드** — 업무 노트에만 추가. 없으면 개인 노트로 간주.
- **리스트(multitext)로 작성한다.** 관련된 회사·기관을 **가까운 순서로** 나열: 내 소속 → 고객사 → 벤더/서비스.
  ```yaml
  client:
    - 우리회사      # 내 소속
    - 고객사A      # 고객사
    - 결제벤더      # 벤더/서비스
  ```
- **`client: 우리회사 고객사A 결제벤더`처럼 한 줄에 이어 쓰지 않는다.** 공백으로 구분되지 않고 `"우리회사 고객사A 결제벤더"` 문자열 하나가 되어 필터가 걸리지 않는다.
- 값이 하나여도 리스트로 쓴다 (`- 우리회사`).
- 첫 번째 값이 **내 소속**이다. "우리회사 업무 전체 보기"는 `client contains 우리회사`으로 걸린다.
- **소속·기관 고유명사는 `tags`에 넣지 않는다.** 반드시 `client` 필드로 (`tags`는 주제 전용).
- 이 필드는 `.obsidian/types.json`에 `"client": "multitext"`로 등록되어 있어야 각 값이 개별 칩으로 표시된다.
- **`client`가 있으면 `20_Work/`로 간다.** 주제 폴더보다 우선한다 (우리회사 배포 문서 → `10_Dev/DevOps/`가 아니라 `20_Work/`).
  - `20_Work/` = 업무 문서 전반 — 거래처 카드 + 그 회사 업무로 작성한 문서. 하위 폴더는 만들지 않음
  - `10_Dev/` = 특정 회사와 무관한 **재사용 가능한 일반 기술 지식** (`client` 없음)
- "업무 노트 전체 보기"는 내장 **백링크** 또는 **Bases**(`.base`)의 `client` 속성 필터로 확인 (Dataview는 이 볼트에 미설치).

## 문서 단일성 원칙

**문서 하나가 필요한 정보를 스스로 담습니다.** 내용을 딴 문서로 빼놓고 찾아가게 만드는 포인터 규칙을 만들지 않습니다.

- ❌ "이 값은 X 문서에 모아둔다 / 여기엔 적지 않는다" → 정보가 두 곳으로 쪼개짐
- ✅ 필요한 정보는 그 문서 안에 직접 기입, 관련 문서끼리는 wikilink로 연결만 (백링크 활용)

### 계정 정보

| 대상 | 위치 |
|------|------|
| **내 계정** — 개인·가족, 그리고 회사에서 쓰는 내 계정 (예: 우리회사 dev Codex) | `40_Personal/🔒 계정 정보` |
| **거래처·클라이언트 계정** — 그 회사의 도메인 관리자·호스팅 등 | 해당 회사 카드 안에 직접 기입 |

`🔒 계정 정보`는 **내 계정 전용 개인 문서**입니다. 거래처 자격증명을 여기로 모으지 않으며, 회사 카드가 이 문서를 자격증명 저장소로 참조하게 만들지 않습니다.

## 공통 문서 구조

1. YAML Frontmatter
2. 상위 인덱스 링크: `> 📂 [[부모 인덱스]]` (frontmatter 바로 다음, 빈 줄 없이)
3. H1 제목 (선택 — 생략 시 파일명이 제목 역할)
4. 본문 — H2(`##`)부터 섹션 시작
5. 관련 링크 (`[[wikilink]]` — 참고 자료 바로 위, 선택)
6. 참고 자료 (선택, 항상 마지막)

### 색상 폰트 관례 (Obsidian 렌더링용)

| 색상 | 코드 | 용도 |
|------|------|------|
| 파스텔 핑크 | `#F9CACA` | 주요 섹션 제목 강조 |
| 파스텔 블루 | `#A8DADC` | 서브 섹션 제목 강조 |
| 파스텔 그린 | `#B5EAD7` | 참고/보조 정보 |
| 파스텔 옐로우 | `#FFD97D` | 주의/중요 표시 |

사용 예시: `<font style="color:#F9CACA">주요 섹션</font>`

## 파일 이름 규칙

```
[이모지] 제목.md
```

- 이모지는 문서 성격에 맞게 선택
- 한국어 + 영어 기술 용어 혼용 가능
- 띄어쓰기 사용 (언더스코어 아님)
- 인덱스 파일: `_[이모지] [카테고리] 인덱스.md` — **`_` 접두사 필수**

### 인덱스 파일의 `_` 접두사

파일 탐색기에서 인덱스를 폴더 맨 위에 고정하기 위한 것입니다.

- Obsidian(ICU 콜레이션)은 **이모지를 숫자보다 먼저** 정렬합니다. 파일명이 전부 이모지로 시작하는 이 볼트에서는 `00_` 같은 숫자 접두사가 오히려 **맨 아래**로 갑니다. `_`만이 이모지 앞에 옵니다.
- 같은 폴더에 인덱스가 여러 개면 허브에 `__`를 붙여 한 단계 더 위로 올립니다 (예: `__🎞️ 감상 기록 인덱스`).
- **wikilink는 `_`를 포함한 실제 파일명 그대로 씁니다** — `[[_💼 Work 인덱스]]`.

> [!warning] 인덱스에 `aliases`를 쓰지 않습니다
> `aliases`로 `_` 없는 이름을 만들고 본문에서 `[[💼 Work 인덱스]]`로 링크하는 방식을 쓰지 마세요.
> Obsidian이 alias 해석에 실패하면 **미해결 링크가 유령 노드로 뜨면서, 같은 인덱스가 그래프뷰에
> 두 개(`💼 Work 인덱스` + `_💼 Work 인덱스`)로 겹쳐 보입니다.** 허브 16개가 전부 두 배가 되어
> 그래프가 완전히 꼬입니다. (`graph.json`의 `hideUnresolved: false`라 유령이 그대로 노출됨)
>
> **링크 대상 = 실제 파일명**을 유지하면 alias 해석에 의존하지 않아 유령이 생길 수 없습니다.

- 인덱스는 `.obsidian/bookmarks.json`에도 등록해 사이드바 북마크 상단에 노출합니다.

## Wikilink 규칙

- 상위 연결: `> 📂 [[부모 인덱스]]` (모든 문서 최상단)
- 관련 문서 참조: `[[문서명]]`
- graph view 연결성을 위해 적극적으로 wikilink 사용

### 부모 인덱스 탐색 규칙

부모 인덱스는 **해당 문서가 위치한 폴더의 인덱스 파일**입니다:

| 문서 위치 | 부모 인덱스 |
|-----------|-------------|
| `10_Dev/Backend/*.md` | `[[_⚙️ Backend 인덱스]]` |
| `10_Dev/Frontend/*.md` | `[[_⚛️ Frontend 인덱스]]` |
| `10_Dev/Server/*.md` | `[[_🖥️ Server 인덱스]]` |
| `10_Dev/DevOps/*.md` | `[[_DevOps 인덱스]]` |
| `10_Dev/Architecture/*.md` | `[[_Architecture 인덱스]]` |
| `10_Dev/Design/*.md` | `[[_🎨 Design 인덱스]]` |
| `10_Dev/Ai/*.md` | `[[_🤖 Ai 인덱스]]` |
| `10_Dev/Standards/*.md` | `[[_📋 컨벤션 인덱스]]` |
| `10_Dev/*.md` (루트) | `[[_💻 개발 인덱스]]` |
| `20_Work/*.md` | `[[_💼 Work 인덱스]]` |
| `30_Tools/*.md` | `[[_🛠️ Tools 인덱스]]` |
| `40_Personal/*.md` | `[[_👤 프로필 인덱스]]` |
| `40_Personal/감상기록/` (tags: `books`) | `[[_📖 책 인덱스]]` |
| `40_Personal/감상기록/` (tags: `movie`) | `[[_🎬 영화 인덱스]]` |
| `40_Personal/감상기록/` (tags: `anime`) | `[[_🌸 애니 인덱스]]` |

인덱스 파일 자신의 부모는 상위 폴더의 인덱스입니다:
- `_⚙️ Backend 인덱스.md` → `> 📂 [[_💻 개발 인덱스]]`
- `__🎞️ 감상 기록 인덱스.md` → `> 📂 [[_👤 프로필 인덱스]]`
- `_📖 책 인덱스.md` · `_🎬 영화 인덱스.md` · `_🌸 애니 인덱스.md` → `> 📂 [[__🎞️ 감상 기록 인덱스]]`

## 에셋 관리

- 이미지/첨부는 해당 문서 폴더 안에 `_assets/` 서브폴더를 만들어 보관
- 경로 예시: `10_Dev/Backend/_assets/mvc-pattern.png`
- Obsidian 문법: `![[파일명.png]]` (볼트 내 어디서든 파일명으로 탐색)
- 문서와 첨부가 같은 폴더에 있으므로, 문서 삭제 시 첨부도 함께 정리 가능
- 레거시 `assets/` 폴더명도 허용 (예: `00_Sandbox/assets/`), 신규는 `_assets/` 사용
- `99_attachment/` 폴더는 사용하지 않음 (폐지됨)
- 문서 이동 시 관련 `_assets/` 내 파일도 대상 폴더의 `_assets/`로 함께 이동
