# /obsidian-index — 인덱스 파일 갱신

새로 추가된 문서들을 해당 폴더의 인덱스 파일에 등록합니다.

- 인수 없음: 볼트 전체 폴더의 인덱스 파일을 검사하여 누락된 문서 모두 추가
- 인수 있음: 해당 폴더만 처리 (예: `10_Dev/Backend`)

**볼트:** `{{OBSIDIAN_VAULT_PATH}}`

> 경로가 `{{OBSIDIAN_VAULT_PATH}}`이면 사용자에게 볼트 경로를 물어본 후 진행한다. 실제 경로가 입력되어 있으면 그대로 사용한다.

## 카테고리 설정
`/obsidian-categories.md` 파일의 **인덱스 파일 매핑** 섹션을 참조한다.

---

## 인덱스 파일 위치

`/obsidian-categories.md`의 **인덱스 파일 매핑** 테이블에 따른다. 인덱스 파일이 없는 폴더는 새로 생성한다.

---

## 섹션 규약

인덱스의 H2 섹션은 두 종류다. 이 구분이 자동 갱신의 핵심이다.

| 섹션 | 성격 | 자동 갱신 |
|------|------|----------|
| `## 📑 목록` | 그 폴더의 문서 목록 | ✅ 여기에만 추가한다 |
| `## 📂 카테고리` | 하위 폴더 인덱스 링크 | ❌ 수동 |
| `## 🏢 회사 카드` · `## 🔗 관련 링크` 등 그 밖의 섹션 | 수동 큐레이션 | ❌ 수동 |

- **추가는 `## 📑 목록`에만** 한다. 없으면 `## 📂 카테고리` 바로 뒤에 새로 만든다.
- **중복 검사는 인덱스 파일 본문 전체**를 스캔한다 (`## 📑 목록` 안만 보면 안 된다).
  다른 섹션에 이미 링크된 문서를 미등록으로 오판해 `## 📑 목록`에 중복 추가하게 된다.

---

## 각 폴더에 대해 수행할 작업

1. 폴더 내 `.md` 파일 목록을 가져온다
   - 제외: 인덱스 파일(`_`로 시작), `_assets/` 내 파일, `.DS_Store`
2. **대상 인덱스를 결정한다** — 아래 **등록 대상 라우팅** 표에 따른다.
   폴더에 인덱스가 여러 개일 수 있으므로 파일마다 대상이 다를 수 있다.
3. 그 폴더의 **모든 인덱스 파일 본문 전체**에서 이미 링크된 `[[파일명]]`을 수집한다
   - 어느 인덱스든 이미 링크돼 있으면 등록된 것으로 본다
4. 어디에도 없는 파일만 대상 인덱스의 `## 📑 목록`에 추가한다
   - 추가 형식: `- [[파일명]]` (확장자 없이, `_` 접두사 포함한 실제 파일명 그대로)

### 등록 대상 라우팅

| 폴더 | 대상 인덱스 | 비고 |
|------|-----------|------|
| `10_Dev/` (루트) | `_💻 개발 인덱스` | 하위 폴더 인덱스는 `## 📂 카테고리`에 수동 |

## 인덱스 파일이 없는 경우

파일명은 `_[이모지] [카테고리] 인덱스.md` — **`_` 접두사 필수**(폴더 맨 위 고정용).
**wikilink는 `_`를 포함한 실제 파일명으로 쓴다** (`[[_💼 Work 인덱스]]`). `aliases`는 쓰지 않는다 —
alias 해석 실패 시 유령 노드가 생겨 그래프뷰에 인덱스가 두 개로 겹쳐 보인다.
생성 후 `.obsidian/bookmarks.json`에도 등록한다. 자세한 규칙은 `/obsidian-categories.md`의 **인덱스 파일 매핑** 참조.

아래 템플릿으로 인덱스 파일을 새로 생성한다:

```markdown
---
status: reference
tags:
  - 카테고리명
description: "카테고리 허브 — 하위 문서 목록"
created: 2026-03-21
updated: 2026-03-21
---

> 📂 (최상위 폴더는 생략)

# [이모지] 카테고리 인덱스

> 이 카테고리에 속한 문서 목록

---

## 📑 목록

- [[문서1]]
- [[문서2]]
```

`## 📑 목록`은 **필수**다 — 자동 갱신이 문서를 넣을 자리다. 없으면 그 폴더는 갱신되지 않는다.
