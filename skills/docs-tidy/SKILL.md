# AI 탐색형 프로젝트 문서 정리

프로젝트를 `README → INDEX → 필요한 문서`로 탐색하도록 정리한다.
사람은 README로 프로젝트를 이해하고, AI는 INDEX의 요약·검색어로 필요한 문서만 고른다.
기본형은 `guide / spec / ops` 세 갈래 구조다. 이 스킬은 코드 구현·배포 지시가 아니다.

## When to Use

- 프로젝트 문서 구조를 통일하거나 YAML 프론트매터·루트 INDEX를 도입할 때.
- 기존 문서를 원문 보존하며 분류하거나, README를 근거 기반 프로젝트 개요로 정리할 때.
- 문서를 추가·수정·이동한 뒤 색인 정합성을 확인할 때.
- 검토만 요청받았으면 읽기와 계획까지만 한다. 사용자 승인 없이 문서 재구성·커밋·푸시하지 않는다.

## Prerequisites

- 정확한 대상 저장소·브랜치·작업 범위를 확인한다. Git 상태와 원격 동기화, 기존 프로젝트 지침을 먼저 읽는다.
- 프론트매터·INDEX 형식은 [형식 가이드](references/format.md)를 따른다.
- 검사 도구는 Python 3.10 이상과 PyYAML 6.x가 필요하다. `uv`가 있으면 스크립트에 선언된 의존성을 자동 준비한다. API 키는 필요 없다.
- 스킬 패키지는 통째로 보관한다. `scripts/`와 `references/`를 빼고 SKILL.md만 복사하면 연결이 끊긴다.

## Procedure

### 1. 조사하고 적용 계획부터 승인받기

1. 기존 INDEX가 있으면 먼저 읽고 목적에 맞는 문서만 연다. 구조 조사에는 파일 목록을 쓰고, 본문 전체를 무차별로 읽지 않는다.
2. 문서 목록·기존 메타데이터·실제 소스 구조·문서 간 링크·실행에 쓰이는 문서 경로를 조사한다.
3. 다음 네 가지를 보여준다: **예정 전체 트리 / 기존→이동 경로 / 새로 작성할 문서 / 수정할 링크·지침·도구**.
4. 이동하지 않을 README·지침·패키지 문서와 이유도 표시한다. 삭제·통합은 이동 승인과 별도로 묻는다.
5. 이 구체적인 계획에 동의받을 때까지 파일을 바꾸지 않는다. 일반적인 “문서 구조를 적용해줘”는 계획 승인 생략 지시가 아니다.

완료 기준: 이동·신규·유지·삭제/통합 제안을 구분한 계획에 사용자 승인이 있다.

### 2. 최소 구조 만들기

```text
프로젝트/
├── README.md             # 사람용 프로젝트 개요·문서 링크
├── INDEX.md              # AI용 중앙 라우팅 색인
├── AGENTS.md / CLAUDE.md  # 사용하는 지침 파일만 유지·보완
└── docs/
    ├── guide/            # 사용·온보딩
    ├── spec/             # 기능·구조·데이터 명세
    └── ops/              # 배포·운영·일정
```

- 코드·자산 등 기존 디렉터리를 위 트리로 대체하지 않는다. 적용 계획에는 기존 구조를 포함해 전체 모습을 제시한다.
- 카테고리는 필요한 것만 만든다. 추가 카테고리는 승인된 목적이 있을 때만 소문자 kebab-case로 만든다.
- 빈 폴더 유지용 더미 문서, 필수도 아닌 카테고리별 색인·인수인계·요구 원장은 만들지 않는다.

완료 기준: 승인한 문서 경로가 준비되고 기존 프로젝트 구조는 보존된다.

### 3. 실제 내용으로 문서 채우기

- 기존 문서가 있으면 **본문을 유지하고** 프론트매터를 붙여 승인한 위치로 옮긴다. 임의 요약·재작성·삭제·통합 금지.
- 기존 프론트매터가 있으면 보존하고 누락 필드만 보완한다. ID·category 충돌이나 기존 규칙과의 차이는 계획에서 합의한다. 추가 메타데이터를 검사 통과 목적으로 삭제하지 않는다.
- 이동으로 깨지는 상대 링크·첨부 경로·지침의 참조를 갱신하고, 이 기계적 수정은 별도로 보고한다.
- 패키지 README·SKILL.md처럼 이동하면 실행·설치가 깨지는 파일은 유지한다. 별도 열람본이 필요하면 이유와 원본 경로를 밝히고 승인받는다.
- 문서가 없으면 실제 코드·설정·테스트를 읽어 프로젝트에 필요한 문서 **2~3개**를 쓴다. 설계만 있는 저장소는 확인된 설계 자료를 근거로 삼고 구현과 구분한다.
- 플레이스홀더·더미·예시 프로젝트 내용 복사 금지. 실제로 확인하지 못한 명령·기능·수치를 사실로 쓰지 않는다.
- 모든 `docs/**/*.md`에 7개 필수 필드를 채운다. README도 docs 아래 있으면 검사 대상이다. 누락 문서를 조용히 제외하지 않는다.

완료 기준: 문서가 실제 근거를 설명하며 기존 본문·메타데이터와 필요한 참조가 보존된다.

### 4. README·지침·INDEX 연결하기

- README는 사람이 처음 보는 진입점이다. 사람과 AI가 함께 읽는 프로젝트 소개로, [형식 가이드 §3](references/format.md#3-readme-구성)의 8개 블록(이름·한 줄 소개 → 현재 상태 → 주요 기능 → 핵심 개념 → 동작 방식 → 프로젝트 구조 → 시작하기 → 문서 안내)을 약 80줄 안에서 쓴다. **근거 파일에서 확인되지 않은 블록은 통째로 뺀다.**
- 명령은 근거 파일(`package.json` scripts, `Makefile`, `pyproject.toml`, 실제 디렉터리 등)에 있는 것만 쓴다. 흔한 명령(`npm run dev` 등)을 추측해 넣지 않는다.
- 상세 명세를 README에 복제하지 않는다. 링크가 많아지면 핵심 진입 문서만 남기고 전체 목록은 INDEX에 맡긴다.
- 기존 AGENTS.md 또는 CLAUDE.md에 “질문을 받으면 INDEX.md부터 읽고 맞는 문서만 연다”와 “문서 변경 시 같은 커밋에서 INDEX 갱신”을 추가한다. 다른 지침을 덮어쓰거나 두 파일을 무조건 새로 만들지 않는다.
- INDEX는 `docs:` 아래 **path·title·summary·keywords만** 담은 YAML 코드블록이다. 프론트매터가 정본이며 본문을 옮기지 않는다.
- 도구를 프로젝트에 둘 경우 승인된 계획에 포함하고 `scripts/docs_index.py`로 복사한다. 기존 동명 파일은 덮어쓰지 않는다. 도구를 복사하지 않고 이 패키지 경로에서 실행해도 된다.

완료 기준: 사람과 AI의 진입점이 연결되고 색인은 문서 정본에서 생성된다.

## How to Run

대상 프로젝트 루트에서 이 패키지의 스크립트를 `scripts/docs_index.py`에 복사한 경우 Bash로 실행한다:

```sh
uv run scripts/docs_index.py build --root .
uv run scripts/docs_index.py check --root .
git diff --check
```

`uv`가 없으면 PyYAML 6.x가 준비된 Python 환경에서 `python scripts/docs_index.py build --root .` 및 `python scripts/docs_index.py check --root .`를 실행한다. 환경 설치는 프로젝트의 기존 의존성 관리 방식을 따른다.

`build`는 검사를 먼저 수행하고 루트 INDEX만 쓴다. `check`는 읽기 전용이며 오류 시 종료 코드 1이다.
기존 INDEX에 별도 본문·프론트매터·다른 형식·추가 YAML 필드·YAML 주석이 있으면 덮어쓰지 않고 멈춘다. 기존 내용을 보존하는 전환 계획을 승인받아 정리한 뒤 실행한다. 오류를 피하려고 INDEX를 임의 삭제하지 않는다.

## Pitfalls

- 이 스킬을 **보관하는 저장소**(claude-setup의 `skills/docs-tidy/`)와 **적용할 프로젝트**를 혼동하지 않는다. Obsidian 볼트처럼 자체 문서 규칙이 있는 곳에 동봉 검사기를 적용하거나 그 규칙을 자동 교체하지 않는다.
- `SKILL.md`는 스킬 패키지 메타데이터를 사용한다. `docs/**/*.md`의 프로젝트 문서 7필드와 다른 계약이다.
- 기본형은 모든 docs Markdown을 포함한다. 원본 번들 예외가 필요하면 먼저 docs 밖 유지 등을 합의하며, 검사에 숨은 제외 목록을 추가하지 않는다.
- 도구는 형식·메타데이터·경로·색인 정합성만 검사한다. summary의 사실성·검색어 품질·원문 보존·본문 링크·README 간결성은 별도 검수한다.
- 이 기본 도구는 docs 내부 심볼릭 링크를 거부한다. 문서·키워드·경로 형식의 확장이 필요하면 먼저 규칙과 검사를 함께 수정하도록 합의한다.
- 커밋·푸시·배포는 각각 승인 범위를 따른다. 문서 정리가 코드 동작이나 배포 승인을 뜻하지 않는다.

## Verification

1. `check` 통과: 7필드·타입·날짜·category·고유 ID·related_files 경로와 INDEX 경로/순서/메타데이터 일치.
2. **docs Markdown 파일 수 = INDEX 고유 항목 수**, 누락·추가·중복 경로 없음. 개수만 같다고 통과시키지 않는다.
3. 원문은 이동 전후 본문 대조로 보존을 확인한다. 승인된 링크 수정은 예외로 명시하고 실제 내부 링크·첨부도 확인한다.
4. README의 기능·개념·구조·명령을 근거 파일과 대조하고, 첫 화면에서 무엇인지 보이는지, 상용구·AI 작업 규칙이 섞이지 않았는지 확인한다. 기존 지침과의 링크·역할 분리를 검수하고 `git diff --check`를 통과한다.
5. 완료 보고에 신규/이동/유지 문서, 문서 수·색인 수, 기계 검사·수동 검수 결과, 미해결 항목을 적는다. 푸시했다면 정확한 원격 커밋·파일을 다시 읽어 확인한다.

패키지 도구 회귀 테스트는 claude-setup 저장소 루트에서 실행한다:

```sh
uv run --with pyyaml python -m unittest discover -s skills/docs-tidy/tests -v
```
