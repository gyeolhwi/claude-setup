# 문구 재구성 규칙

원본 자료의 제목·문장을 그대로 옮기지 않고 슬라이드 톤으로 바꾼다. 기준 사례는 `presentation.md → ppt.pptx`.

## 1. 섹션 이름 — 2~6자 명사형

| 원본 | 슬라이드 |
|---|---|
| 왜 만들었는가 | 도입 배경 |
| 작업 흐름 (Workflow) | 제작 흐름 |
| 개발 진행 현황 | 구축 현황 |
| 웹 플랫폼 vs 봇 스킬 — 두 가지 방향 | 봇 전환 구상 |
| 기대 효과 | 기대 효과 |

질문형·구어형·영문 병기·부제(— …)를 빼고 **명사형 한 덩어리**로 만든다.

## 2. 슬라이드 제목 — 15자 안팎, 명사로 끝남

| 원본 | 슬라이드 |
|---|---|
| 기존 업무의 문제점 | 기존 제작 방식의 한계 |
| AS-IS / TO-BE 표 | 자동화 전후 비교 |
| 단계별 상세 | 단계별 주요 기능 |
| 고객사 프로파일 시스템 | 고객사 프로파일 구조 |
| 캡처 파이프라인 — 핵심 기술 | 이미지 생성 파이프라인 |
| 정량적 효과 | 도입 효과 |

- 마침표·물음표·느낌표 금지. "~하기", "~에 대하여" 금지.
- 업계 영어 약어(AS-IS/TO-BE, Phase, STEP)는 청중이 일반 구성원이면 한국어로(기존/자동화 후).

## 3. 리드 문장(lead) — 한 문장, "~합니다" 체

슬라이드가 말하려는 바를 한 줄로. 원본 문단은 요약해 한 문장으로 줄인다.
> 각 고객사의 팝업 규칙을 프로파일로 등록하고, 정보 입력만 하면 자동으로 이미지를 생성하는 플랫폼을 구축합니다.
> → 고객사별 팝업 규칙을 프로파일로 등록하고, 정보 입력만으로 이미지를 자동 생성합니다.

## 4. 항목 — "키워드 제목 + 짧은 설명"

- 원본의 문장형 불릿은 `title`(2~8자 명사) + `desc`(한 줄)로 쪼갠다.
  `단순 반복 작업에 **매회 30분 이상** 소요` → `단순 반복 작업` / `매회 30분 이상 소요`
- 카드 불릿·표 칸은 **명사형 종결**(~판별, ~지정, ~반영). "~합니다" 쓰지 않음.
- 가운뎃점(·)으로 나열을 압축: `날짜/요일` → `날짜·요일`.
- 마크다운 강조(`**`)는 쓰지 않는다. 강조는 형태가 맡는다(stat, highlight, closing).

## 5. 숫자 — 크게 뽑는다

원본에 핵심 수치가 있으면 `stat-list` 의 `stat` 또는 `closing` 의 `stats` 로 꺼낸다(30분+, 83%, 0건).

## 6. 기술 용어 — 청중에 맞춰 풀이

청중이 비개발자를 포함하면 `spec-list` 의 `desc` 에 쉬운 말 풀이를 붙인다.
> Zustand → 입력한 날짜·배경·문구를 한곳에 기억해 모든 화면에 똑같이 반영

## 7. 발표자 노트 — 말하는 어투 2~4문장

슬라이드 글을 반복하지 말고, 왜 중요한지·다음으로 어떻게 이어지는지를 말로 푼다.

## 8. 내용 범위

- **원본 자료(브리프·기획안)에 없는 사실·수치·계획을 만들지 않는다.** 표현만 바꾼다.
- 브리프에 없는 정보(수치·일정·사례)가 꼭 필요하면 지어내지 말고 사용자에게 질문한다.
